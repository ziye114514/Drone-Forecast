# 圆饼机体：周期支持与未来法线预测（2026-10-28）

用户已明确：机体不分机头机尾，运动方向不由机头朝向决定。
同型平行桨轴、四桨都计入时，任意编号置换不会改变sum(T_i)。
漏计、重复计数、可见集合改变或把隐藏点当观测才可能影响总量。
逐桨差速反推力矩需要空间位置关联，但当前无须把稳定电机编号作为二维合力预测前提。

## 本轮已实现

- normal_turn_forecast.py：无向平面法线采用两倍角展开，估计当前转动趋势；不使用机头或桨盘编号。
- 只对已知输入方向的变化积分，既有未知合力不随机体旋转。
- 当前平面观测不足、无推力代理、图像运动不支持平移时不加额外修正。
- 静止、机体平面周期波动的91个受控时刻不产生额外转向位移；不代表原检测或位置状态本身零误差。
- temporal_period_support.py：100ms内按原生像素ID去重，同频簇仍需16个不同像素，
  至少2个源窗口、4个当前同频像素。当前频率由当前点给出，历史仅确认支持。
- 原始时间戳/极性及SDK周期测量均保留。只将已有频率点平移到当前ROI判断归属，
  没有把运动补偿事件重新喂进周期观察器制造周期。
- 环带共同闪烁、同一个热像素反复出现、过期历史均拒绝。
- 新候选target-candidate启用未来法线；--no-normal-turn-forecast保留同输入控制。
- --temporal-period-support为显式实验选项，会启用周期全像素。当前没有证明它改善位置精度。

## 未来位置如何改变

原有Singer条件净加速度预测保留。另加一项：
delta_p(h) = integral_0^h (h-s) exp(-s/tau) [R(omega*s)-I] a_known ds。
a_known = effective_gain * input_u。只旋转已知推力贡献；d、重力与风/阻力不跟着旋转。
tau沿用0.35秒。无转动/无资格时delta_p为0。
当前法线的正负号和任意桨编号置换不改变转动趋势；运动方向仍由速度和合力共同决定。
这是图像平面条件外推，不是恢复真实3D姿态或推力，也未预测尚不可见的未来控制指令。

## 实际证据

同一冻结侧视输入：26目标0.4秒均值43.2745→42.7192px，P9580.6014→77.5407。
实际8秒RAW：240源175当前171有效；同一最新输入关闭方向演化42.8050、开启42.4040px；
P9577.9994→77.0781。相对旧RAW数值也有定位/异步时序差异，不能把全部差值算给新模型。
无四桨锁定仍能做该方向预测，证明此分支不依赖稳定桨盘编号。

train2固定40–46秒：时序支持恢复4次合格周期，3次当前推力代理，7次方向校正。
同输入无周期控制62.6464，周期62.6780，联合62.6796px；没有精度收益，维持实验选项。
全程180源111当前107有效，没有通过删掉坏预测变好。

性能：侧视全8秒约49.97处理FPS含无目标轻负载，需看固定前4秒与延迟；
另一录像实际28.95FPS，43.432899秒出现一次约3019.93ms读取等待，生产端原生解码计时约3048.90ms。
这次阻塞不能归因于机体模型或新增几何公式；USB/SDK/系统调度根因尚未确定。
未删除慢帧，整体尚未达到30px/稳定低延迟30FPS。

## 运行

SDK环境中，按既有配置使用run_fast_structure.py的target-candidate即启用法线演化。
最新完整候选仍配合sdk-avx2、rigid-motion、tangent-disturbance、structure-guided-nn；发布ZIP保持冻结。
旧方向控制加--no-normal-turn-forecast。
周期试验另加--temporal-period-support；目前不建议把它描述成已验证精度优化。
空间相位/真实机械RPM与完整力矩反解未因本轮改变为已验证事实。
