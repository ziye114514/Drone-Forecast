# 从频率峰到可预测的周期证据（2026-10-27）

这次继续DDHF方向，新增模块而非更换默认预测器。原工作位置核心、旧检测/预测基线及GitHub预览ZIP保留。

## 1. 筛选机制实际改了什么

`predictive_harmonics.py`将一个33.333ms窗口分成前、后两半。前半窗搜索120..960Hz、15Hz步长的四阶谐波模板，保留至多两种频率假设；后半窗只检查已经选定模板能否预测事件极性与相位。
模板搜索不读后半窗极性，避免在同一批随机事件里挑最大峰再拿它作证。各半窗需至少6个事件、足够时间跨度和覆盖，防止单次边缘扫过/突发被当成持续周期。

后半窗模板投影去均值，并按投影平方/模板能量形成单侧界，补偿两模板选择。这个界依赖“给定时间戳时，随机极性独立且分布平稳”的理想零假设，**不是已校准的事件相机误检概率**。共同周期照明预期会通过：模块输出周期证据，不能单独判定无人机、真实RPM或完整桨盘。

固定同输入控制：4种事件量12/24/48/96，每种16像素，旧本地NDFT参考在64随机、64单次边缘中各接纳64；新方法各0。已知周期在24事件时15/16通过、48及96事件时各16/16，12事件时0/16，弱信号召回有代价。共同闪烁在48/96事件时仍全部通过，保留这个未解决限制。

这不是DDHF作者实现或论文结果复现。原先`harmonic_pixels.py`仍在，供对照。

## 2. 过去速度对齐与实际窗口

`native_event_alignment.py`逐字复用项目stage21的warp函数，包装过去速度检查；没有导入整个历史前端。速度来源必须早于整个当前窗口，最大龄期160ms。只平移/量化空间坐标，保留原始时间戳与极性，原事件数组不改。零速度数值精确，未来速度拒绝。

同三个自采RAW窗口，先未经对齐读取并缓存原生事件；后续对齐、几何和GPU小试复用同一缓存，没有反复读取RAW。

|窗口|未对齐周期像素|过去速度对齐后|
|---|---:|---:|
|26.466402s clear|1942|1656|
|27.499725s partial|719|835|
|110.765559s side|131|917|

像素数增加不等于召回率或精度提高。侧视速度约(252,243)px/s，33.3ms对应(8.4,8.1)px平移；因此固定像素的周期会被整机运动破坏。清晰段数量反而减少，不能把补偿宣传为处处有益。仍未补偿姿态旋转、尺度变化、视差和窗口内加速度。

## 3. 频率如何接几何

直接用周期掩码裁剪原轮廓，会丢掉外缘并产生人工切口；小试中清晰桨盘拟合中心会移动、侧视碎裂，所以这条操作没有部署。

`harmonic_arc_split.py`改为：周期区域只提供分组种子，将**原20ms计数掩码经原形态学后的外轮廓点**分组；拟合器只看这些现有轮廓点，不看切口边，不以种子质心当桨心。
继续使用既有AMS/残弧拟合及资格：覆盖≥0.48、边界支持≥0.6、条件数≤1500、中心sigma代理≤3px、角度sigma代理≤15°；没有降低门槛。完整拆分还须各子弧与联合几何都合格，不强迫得到四个。

受控两个重叠椭圆可得到2个合格子中心；单个椭圆即使人为放两个种子，也不能变成两个电机；无周期种子不拆分。
实际侧视两处粘连都未通过完整双桨拆分；但其中一条原弧合格，sigma代理1.20px、边界支持0.833、条件数7.15。同一父轮廓直接使用相同残弧拟合器未合格。该弧单独作为部分候选保留；没有赋物理电机ID、没有新四桨姿态或真实中心精度证明。
其余子弧主要卡边界支持约0.46或中心sigma代理3.63/5.84px，仍拒绝。

## 4. 速度优化与当前边界

`predictive_harmonics_cuda.py`用现有PyTorch/CUDA批量正余弦与分段归约。长度由CPU验证后跳过重复GPU校验；当前三个窗口与CPU掩码逐像素一致。
RTX5060 Laptop本机，整组件包含CPU像素分组、传输和CUDA同步。批量版清晰/partial/侧视平均约86.5/40.8/58.3ms；同项目既有seed141000固定25%像素、每个所选像素保留所有时间戳后，约61.0/36.3/45.6ms。冷启动另计。
这是组件结果，既不是整个RAW预测系统FPS，也不是稳定33.3ms时限。空间采样后的黑色未测像素不能算作“非周期”，不能裁掉相应几何边界。

另一项缩小频率库的试验：仅用上一时刻有效频率3–5项作候选，CPU减少到253–616ms，但侧视只剩108合格像素，低于宽频库917，说明此前周期状态可能有偏差。不能为了快而永久锁死旧频率，需要宽频重发现/失锁恢复。

## 5. 复现入口与下一步

基础/SDK Python运行：

```text
python tools/check_predictive_harmonics.py <new-output>
python tools/probe_predictive_harmonics.py <new-output>
```

第二条读取事先固定的自采3窗口与已有因果整机框，后者只用于显示和几何ROI，逐像素周期筛选本身处理整帧事件；不是新的独立定位器评估。
GPU Python运行`tools/bench_predictive_harmonics_cuda.py <new-output>`，加`--sparse`选择既有25%固定像素；输入为本轮已缓存窗口。

下一步优先两项实际改进：

1. 把合格单弧送入五圆模型的可观测方向/部分信息更新，未初始化时仅作局部轴线证据，不造隐藏桨心或延长完整姿态资格。需要连续短窗考察，当前只有3帧小试。
2. 将低频宽带重发现与高频小频库验证分工，带失锁恢复；进一步减少GPU启动/同步开销。新增观测只有在信息和延迟都合格后才进入预测。

真实轨迹误差本轮未重新评分，不能宣称下降或优于运动学。主预测入口仍保留旧默认。
