# 实时通道的精简源码候选包

用户游戏期间曾暂停测速、GPU试跑和RAW重放，之后明确关闭游戏并恢复。轻量整理已经完成，目前进行短RAW接线与机制对照；不能把源码整理本身算成精度或速度提升。

当前live入口的运行依赖已与历史测速脚本分开：

- `live_worker.py`负责当前共享画面的请求、推理和NMS。原研究入口继续使用未改动的`research/stage47/worker47.py`。
- `event_drone_forecast.detector_backend`提取45原有预处理、CUDA Graph/IO binding和NMS函数；要求显式模型路径，导入时不读取历史缓存或创建CUDA会话。
- 独立SDK生产进程拥有噪声和周期引擎；父进程直接测量当前周期包，不再为同一用途创建第二套引擎。旧thread生产器仍保留自身引擎。
- 源码指纹覆盖真正使用的包内位置核心、检测后端与可选几何，不再要求23/107/154等未使用的历史文件存在。
- `--verify-frames`时，tracking额外保存生产者/父进程/GPU画面SHA，方便定位共享传输问题。不开校验时不额外计算哈希。
- 启动器提前拒绝发布频率高于跟踪频率、跟踪频率超过50Hz，以及thread生产器搭配frames传输；避免配置错误直到GPU启动后才暴露。

另有可选`--startup-sync reader-ready`，仅用于process生产器：SDK完成文件定位、预热原生状态并取得首个待发布切片后先等待，主进程再完成检测预热、打开输出和发布器，最后放行回放时间原点。默认`none`保留原顺序，不改变预测公式。取消、错误和超时均不放行；不重启失败作业。

预测数学、检测阈值、权重、噪声默认值与有效性门槛没有调整。`frame_transport`仍默认events；frames仍为可选实验。

## 已完成的轻量检查

新旧预处理、NMS和参数的抽象语法树完全一致；ORT后端仅删除“未传模型时回退历史权重”的分支，实际调用仍显式传模型。新旧GPU请求循环在模块别名替换后也完全一致。检查只解析源码，不导入NumPy、SDK、Torch或ORT。

源码启动器和移到output下的精简目录均通过CLI合约检查：dry-run不创建子进程，不读RAW内容；不合法组合在启动前报错。精简入口仅提供live模式，配置文件无法偷偷切到未打包的research流程。

这些轻量检查**没有证明完整RAW/CUDA运行或性能收益**。恢复后当前源码已完成events/frames与启动同步的短接线，仍需区分源码目录和移出目录的候选运行；具体完成范围以`output/live_startup_transport_20261025`与handoff为准，不能沿用旧版本实跑分数。

## 生成与使用

```text
python tools/build_live_runtime.py --output <新的精简目录>
```

工具按明确白名单复制约40个小文件并生成ZIP、每文件SHA和交付清单，不读取RAW或权重、不安装依赖、不启动GPU。包含位置核心、未修改的FilterPy文件与MIT许可证、两个可选周期脚本及当前live代码；不包含完整历史研究链、HelixTrack、SDK二进制、模型、私有配置或个人数据。

精简目录中：

```text
python live.py --help
python live.py run --config <你的配置.json> --raw <event.raw> --output <新输出目录> --start 110 --duration 2 --dry-run
```

配置模板为`configs/live.example.json`。SDK Python和GPU Python仍须分别拥有兼容依赖与权重；这只是准备好的源码候选包，不是安装包、干净机器验证或实时相机驱动。只有用户明确恢复负载实验后，才执行去掉`--dry-run`的命令或`doctor`。

`--startup-sync reader-ready`目前是可选机制，尚未成为默认。原生切片在放行前不送给估计器，放行后仍按源时间节拍释放。定位耗时计入完整启动时间，不伪装成已经实时处理。标准库检查仅证明状态机与源码调用顺序，真实效果仍看短段实际结果。

本轮首个目录`output/live_runtime_source_20261025`是中间候选，后续版本另存，不覆盖。以最新交接记录中的目录与SHA为准。此前0.3.1位置wheel及841文件完整源码ZIP是历史已验证产物，没有包含本次全部改动。

## 恢复后的实际接线结果

frames两次传输P95约1.56/1.43ms，对比同步events约17.17ms；但有效数重复为5/6与4/6，暂不能认为稳定提高可用率，更不是精度提升。文件缓存、温度和调度未严格控制。另0.4秒周期分支因处理/传输负载有8个过旧输入，3次跟踪、2次发布、0次有效，继续默认关闭。
