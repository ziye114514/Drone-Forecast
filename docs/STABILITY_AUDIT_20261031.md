# 跨片段误差与持续30Hz修复记录

用户要求查清28px与60px差异、直接优化，保留基线，关注稳定误差和稳定帧率。目标仍未完成。实际结果位于 `output/stability_audit_20261031`，各RAW目录保留当次源码与协议。

当前发现：

- FRED0：0.4s平均28.288px、目标对角线中位44.82px；train2：60.159px、对角线183.43px。平均相对框对角线误差分别0.632、0.322。绝对像素目标仍保留，归一化只是解释场景差异，不能用它宣布25px达标。
- 把train2当前估计位置替换为当时人工中心，平均未来误差仍55.606px，主要还有速度/加速度估计和未来运动延续问题。过去标注构造的CV只是回溯诊断，不是不可突破的误差下限。
- 七段既有数据已反复用于开发，不存在全项目严格独立留出；上游训练可能覆盖全部FRED，详见MODEL_CARD。不能排除开发集过拟合，亦不能仅凭跨段差异证明某个模型过拟合。
- 原生RAW时间戳在两段均有完整微秒余数，未发现视频帧率量化。train2的160ms机体像素事件数中位12，清晰37、侧视18；重复事件本身不证明周期，也不能直接换算机械RPM。
- 历史FRED7开启 `--current-nn-on-loss`，当前30Hz配置未开。小目标延迟NN框的当前光流转移失败会造成断跟；正复用既有当前帧恢复功能测试，未用预测框伪装检测。

固定规则试验：机体中心采点60.159→60.678px；成熟自身残差校力60.159→64.545；分方向恢复加速度→64.093；直接用拟合速度端点→62.359。都不是可推广精度收益，未覆盖原默认。跨六段保留同起点、漏失及负结果，不用逐片段调参数抹平。

计算优化：新增可选 `--jit-huber`，解原来的白化Huber目标，梯度不能认证就回原SciPy；无fastmath，首次编译单列。七段冻结输入全部资格判定不变、未来点最大变化8.43e-7px；只在有稳健拟合的片段有效。新增 `--jit-conic-residual` 融合原残差计算；60个相同真实RAW/固定框的全部几何逐项相同，64个轮廓残差差异≤2.23e-16px。两个选项不是新检测器或新物理定律。

清晰实际RAW相邻两次：仅Huber31.75处理FPS、滞后P95 171.68ms；再融合残差34.71FPS、136.70ms。独立发布仍约30Hz，97/120→105/120有效。但同输入几何组件P95并未改善，运行条件和异步差异不可忽略，不能把相邻变化全归编译优化。清晰段Huber实际调用0次。

FRED8预先固定窗口20–24s（不按预测误差挑选），原/编译配置源预测逐项相同：39.353px、P95 83.882、16/19预测目标可用，73/120当前图像观测。发布约30Hz，81/120有效。其全链P95低于10ms但仍有检测断续，说明计算吞吐和当前观测召回是两种问题。

新的可选方向：`--weak-body-continuation` 借鉴ByteTrack的低分框续接，复用当前同次NN输出和既有空间门槛；不允许低分初始化/抬高置信度，仅在300ms内有真实高分NN锚点时使用。`--wide-motion-search` 让过去状态只扩大当前LK搜索，超过旧0.4框位移门槛还须12内点/.75/9px²和中心凸包支持。二者仍在试验，尚未默认。

所有已有发布ZIP、模型权重和保护目录保持原样。没有测得真实推力，也不把无效发布心跳计作30Hz有效预测。

## 净力补充：保留小收益，但未默认

新增可选 `--position-net-force`：仅在当前周期、保持力、合格光流加速度均不可用时，使用过去真实机体位置估计当前图像净加速度，继续同一Singer积分。保持原p/v，没有新并行预测器；已知推力分支优先，绝不称真实推力。

固定规则、固定观测：FRED7 81.818→75.895，FRED9 54.180→53.756，train2 60.159→60.661。预登记FRED10固定同18输入66.850→65.475、P95 147.127→134.929，小收益保留。实际RAW两次原18起点仅17共同可用，65.450→66.527；相同实际查询共同12反而76.197→80.148。因此尚未默认。不是因为收益小，而是完整流水线没有保住收益。

下一卡点更加具体：按墙钟余量决定NN恢复，使预测计算量的变化也会改变刷新时刻／后续观测。需要进一步把检测刷新调度与预测模块耗时隔离，再接入净力补充；不要在FRED10错误上调权重来掩盖此问题。源码、同输入结果和真实负结果均保留。
