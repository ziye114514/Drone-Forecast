## 1. 先解决“主峰属于谁”

在26.499735秒，当前四个桨的SDK事件频率分别为303.25、230.21、256.48、284.43Hz。新整机空间方差主峰231.875Hz，对应其中一个桨；主峰变化既可能是转速变化，也可能是占主导的桨换了。

因此不能把整个无人机的最强频率平方直接当成四桨总推力，也不能因机体无需机头/机尾就忽略测量集合变化。四个真实当前频率的平方和确实不需要身份；只有部分可见或频谱成分缺失时，才需要明确哪些项来自观测、哪些来自短时先验。

先复用已有 `VisibilityPeriodProxy`、`ConservativeSlotPeriodProxy`、`RotorThrustBankProxy` 的同源/短先验分工，以及 `SharedPhaseFFT` 的相位与谐波检验。已有复用实验在 `output/fred_transfer_20261029/frequency_gauge`，侧视没有总体收益，不要从头重复做一次。新空间方差应先作为独立观测校验或多峰候选来源，不另造一套运动预测器。

## 2. 独立RPM只需要一小份静态数据

[effqpdet官方项目](https://github.com/radimspetlik/effqpdet)提供高分辨率事件桨叶检测、频率和椭圆姿态代码，公开数据覆盖1100–8200RPM及0/10/90度。其README没有在本次访问中说明RPM是实际测速还是控制设定值，拿到数据后应先查元数据，不能提前称作高精度测速器真值。

先选正视、斜视、90度各一个连续文件，复用其原始事件、设置和参考数值，比较现有SDK与新轴向空间方差。只需确定单位、叶片通过频率/机械转频转换、2倍/半频错误及静态角度退化。不要为这一步下载整个FRED、生成大量预测视频或搜索轨迹误差超参。

本次独立数据集HTTPS HEAD证书校验失败，记录在 `output/fred_transfer_20261029/independent_RPM_dataset_access.json`；未绕过证书、未下载大文件。`E:\dataset\software`只读文件名搜索未发现effqpdet/相关RPM文件匹配，不能据此认定其他位置一定没有。

作者代码需要C++17、Metavision SDK、Boost、yaml-cpp、HDF5和Protobuf，CMake含绝对路径。先检查能否只复用其检测核心与数据格式，不要先在Windows安装整套无关依赖。代码许可此前核验为Apache-2.0；数据本身的使用/再分发条件另查，原作者要求引用论文。

## 3. 通过后再进入合力与推力变化率

四桨：当前可信事件频率集合形成无身份平方和，保持与过去相同的频率/谐波标尺。

三桨/二桨：几何补出的桨心不是转速观测。缺失项只作带年龄、误差范围和失效条件的先验；集合变化不可当作真实推力突变。侧视只有线时只约束图像轴，在弱透视条件下近似平面投影，不能声称唯一三维法线或真实推力。

当前推力趋势包括幅值变化和法线变化，即Ṫn+Tṅ；未知合力不跟着已知推力一起旋转或缩放。已有 `SourceAwareThrustTrendForecast` 实现同源趋势，不能把保持幅值当新周期。先让它获得可信且持续的输入，再判断是否改善相同预测起点，避免继续增加参数掩盖缺观测。

像素加速度还含距离/成像尺度的变化。保持实际推力不变时，无人机远近变化也会改变px/s²，所以当前有效增益并非单纯推力系数。只有当前可信桨盘长轴或已锁定模型能提供尺度时，才可探索按成像尺度调整输入；不能直接用姿态变化造成的整机框收缩当距离变化。这一项没有实测改进证据，先不要接入默认。

## 4. 实时工程只保留有用的低成本改动

精简输出v2和精简历史是独立可选开关，原默认完整诊断保留。滚动RAW读取保留全部事件场，但异步NN调度改变实际预测，自采另一段尚有约2.3px回退，因此不默认替换。

下一步若改异步部分，优先记录/使用源时刻、当前转移质量和答复年龄，比较已有相同起点，不以删除慢帧达到FPS。处理能力大于30、新观测29Hz、每帧准时完成是不同指标；先压已有延迟峰值，无需立刻购买更快设备。
