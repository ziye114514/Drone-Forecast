# 接下来做什么

按可用性排序，不以论文突破或50Hz为前提。

1. **完成模型获取和干净环境复现**：提供合规的参考权重获取或训练/导出步骤；把SDK、CUDA和Python配置明确化。当前统一启动和自检已经有，源码安装核心尚未抽完。
2. **5Hz预测发布与异步最新观测调度**：保留原始周期时间戳，避免完整处理50Hz帧造成FIFO延迟；记录事件截止时刻、实际发布时刻、数据年龄和端到端延迟。先实现机制，再做一个短段测量。
   已在独立live位置通道实现并跑短段；总体发布4.0—4.5Hz，仍有无效/空档，下一步是连续性和低频变向精度，不把目标频率写成达标。
3. **稳定时序状态**：用当前姿态证据和结构记忆分别控制回退，处理出画、长漏检和同一目标复锁。降低框尺寸变化对速度/加速度的污染。
4. **继续打包完整RAW运行链**：0.3.1已提取position位置/速度/加速度与外推核心，632次实际输入数值保持，wheel移出原目录与独立pip安装通过；完整SDK读取/低延迟调度/CUDA工作进程仍依赖源码目录。下一步提取这条闭环，逐步消除历史路径，保留本机依赖与干净机器复现的区别。
5. **再做桨盘信号是否有效的机制改进**：优先解决机械周期与多电机混合；允许可靠线索短时生效，不强迫四桨永远全见。没有独立增益就保留为诊断输出。

当前不优先继续微调大量物理权重，也不靠新增阶段编号当作项目进展。工程成果以陌生用户能否运行、输出是否清楚和失败时是否可靠回退衡量。
