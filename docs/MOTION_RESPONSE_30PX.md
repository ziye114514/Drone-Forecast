# 2026-10-28—29：当前加速度与未知合力衔接

目标仍是二维图像中0.4秒预测平均欧氏误差低于30px，同时关注30FPS处理能力、有效观测率和延迟。
本轮最终实际侧视RAW达到34.6049px/P95 72.5433px；同输入旧版本42.4924px。另一录像59.7896px/P95 115.6108px，目标未完成。最终侧视前4秒与清晰2秒处理能力34.0988/31.4464FPS；逐帧准时率与积压仍不满足稳定低延迟30FPS。

## 主线保持五圆模型与二力反馈

原生ON/OFF → 当前整机ROI → 原弧/椭圆与五圆约束 → 当前平面轴线和可见模式 → 原生周期代理 → 已知相对推力输入和未知合力 → 未来位置。
完整四桨、条件三桨补全、部分两桨与未决轴线保持不同资格；axis_only并不等于恰好看到两个电机。
机头和桨盘编号不作为合推力预测的前提。没有新增传统加速度预测器或第二个位置滤波器。

## 新增的实际改动

1. `curved_flow_motion.py`：过去0.35秒的速度曲线提供当前加速度端点。先用早期观测拟合，检查后两条已经发生的速度；按曲率不确定度连续收缩，保留位置一致性门槛。加加速度只帮助估计当前值，不直接断言未来控制。
2. `fast_force_response.py`：增益有足够正向证据后按精度更新，避免从任意默认值再等待固定1秒。相同成熟数据不重复计为新证据；增益换算时以当前输入保持加速度坐标基准。
3. `endpoint_force_balance.py`：输入历史缺失而无法积分平衡时，用合格当前加速度约束条件未知力：d=a_current-k*u_current。若切向已更新，仅补剩余法向；用工程不确定度比较限制更新。它不分别识别重力、风、阻力或质量。
4. `adaptive_force_memory.py`：只用已成熟的自身位置观测学习净加速度持续性，融合原Singer先验与恒净加速度先验。后续已经过有效增益标定且当前轴线/净加速度合格时，周期缺失仍可沿用该合力持续性；不补造转速。
5. 全椭圆路径去掉仅对部分弧假设有用的面积/百分位遍历，并复用已有边界残差。60个固定时刻的全部几何和结构输出逐项相同，距离计算722→444次。

## 速度与周期恢复

实际端点版侧视前4秒和清晰2秒均单列处理能力；具体数值见本轮报告，不能把含无人机缺席时段的全8秒吞吐当检测FPS。
清晰段一次有3.109秒原生解码停顿，11.20FPS；增加CPU/等待记录后的另一次31.88FPS，没有复现停顿。原因尚未定位，后一次较快不等于修复了SDK/存储问题。

`aligned_period_recovery.py`复用既有SDK strict7/fast3，在过去160ms实测位移对齐的ROI上重试：strict7无新增，fast3恢复8个合格时刻，但0.4秒无改善且较慢。
`body_period_stream.py`改为固定机体坐标系持续处理，每个事件只送入一次；fast3新增31个合格周期时刻，当前力输入3→26，单独接入反而使误差59.79→65.94px。端点平衡重放修复后60.95px，仍比原生通道差，因此保持可选。
该通道保留16像素/频带/环带规则，但坐标变换后的参考像素不是独立原生像素票；不把其输出直接称作机械RPM。合成移动周期源、单次移动边缘、全局闪烁仅是机制检查。

另一个未接主线的短试验是120ms净加速度惯性续接：侧视评分不变，另一录像59.79→66.31px。近期速度与不确定度仍可能允许真实制动前的旧加速度，因此不能仅为通过目标延长保持门槛。原失败和源代码保留在本轮net_acceleration_hold目录。

## 使用与对照

工作版本`run_fast_structure.py --target-candidate`已启用曲线、证据增益、端点平衡、合力持续性及标定后缺周期延续。
原生周期仍为默认，运动对齐恢复和固定机体周期流默认关闭。

对照可分别使用`--no-curved-motion`、`--no-evidence-gain`、`--no-endpoint-force-balance`、`--no-adaptive-force-memory`。
本轮记录的对照还保留--tangent-disturbance。仅关闭最后的缺周期延续用`--memory-requires-current-period`。
可选SDK AVX2/刚体位移/结构控制NN须仍显式启用；单机短测不是30FPS稳定性保证。
