## 做了什么

1. 新`nn_rotor_fusion.py`复用GPU原生ON/OFF前端、FastStructure、QualifiedCenter和RotorThrustBankProxy。NN只给ROI及当前位置；桨叶几何/周期来自原生事件。四/三/部分二桨与侧线分别处理，隐藏桨力归d，几何补点不补RPM。
2. SDK只读原RAW补存26–30s清晰原生NPY缓存；侧视/另一录像复用阶段164/165缓存。NN时间与原生包边界不同，`NativeCache.window`严格重拼`[round(t*1e6)-33333, round(t*1e6))`，不借未来状态或事件。
3. 第一轮用相同NN/KLT观测、共同新7状态、相同噪声做四组消融；新骨干较弱，未因赢弱基线就判成功。
4. 新`nn_rotor_residual.py`保留旧NN全部p/v/有效性/光流，仅改力输入和姿态。`legacy_exact`复原旧物理预测最大偏差3.2e-9px；直接替换新桨叶力依然退化。
5. 新`nn_rotor_gate.py`保留旧完整预测，加原生桨叶候选增量，用**已到期自身NN位置**学0–1权重。沿用已有AdaptiveForceMemory的Huber/岭/衰减/历史，不使用坐标标签。没有第二个位置跟踪器。新`ObservedForceGauge`避免可见集合更换造成假加速。
6. 加`native_evidence_only`归因控制：真实当前周期/姿态资格完全相同，仍允许未知力学习/记忆，仅把已知输入数值置零。它用来区分周期数值和“允许更新未知项”的开关作用。

## 真正卡点

- 清晰120个NN时刻：18four、4three、5partial_two、71axis_only；完整四槽当前周期2次。侧视132时刻无四槽；另一段仅3次周期输入。几何模式insufficient仍可能有当前可见锥线法向，需读pose_source，不能只按模式名误判全无当前方向。
- 新可见力分支有效增益更新**三段均0**，仍默认k=200像素动力学尺度。不是真实推力/牛顿/机械RPM标定。
- 完整候选对同资格零已知输入候选的0.4s差异：侧视86次活动均值0.203px、最大0.756；清晰83次0.516px、最大2.235；train2 3次0.032px、最大0.091。输入数值杠杆小，不能解释几十px大误差。
- 侧视111.2/111.4s根据过去到期NN位置学出正权重，当时人工参考却更差；111.6改善后权重退0。自身NN位置只是带偏差教师，且0.4s成熟延迟不能预见新控制变化。不要靠在这些点上调“最少3行”等门槛强造收益。
- 特征平均清晰43.81ms/侧视46.21ms；候选+门控约1–4ms。train2平均17.21ms含76个无原生窗口的暖启动，不能拿它当实际特征能力。**本轮没有RAW+NN完整实时测速或30Hz证明。**
