# 侧视局部时间相位：低负载原型与下一步

2026-11-01，接续阶段163。主运行版本及实测仍见HANDOFF_20261101_PHASE_SPEED163.md；本批没有启动RAW/GPU负载、没有修改默认预测链路。

## 为何当前方案卡住

侧视没有合格共享平面，因此空间相位41次清晰合格、侧视0次。继续完善椭圆反解不会自动给侧视增加信息。应在现有ON/OFF桨叶支持内，直接估局部时间周期，而不是先补齐五圆或确认每个电机身份。

速度方面，33.3ms是整条处理预算。当前GPU和CPU串行、频谱和原生几何反复计算，局部匹配约11ms收益不足以让5–7FPS变成30FPS。双缓冲只能重叠独立成本，不能让单个超过预算的阶段自动达标。因此要先削减锁定阶段的频谱搜索与几何求解，再用有界流水线接起来。

## 本批实际实现

新local_temporal_phase.py，不需要椭圆、桨心或共享平面：

1. 只接收上游已确认桨叶支持的原生事件；未提供支持资格直接拒绝，避免把任意周期灯光叫无人机。
2. 用已有机体平移速度将事件对齐到当前机体中心，按24px局部块分组。这里的块不是电机编号，也不是桨叶数量。
3. 每块保留当前至多8个频率候选，直接使用原生时间戳计算前半窗的ON/OFF两阶周期模板，再用后半窗独立检验相关性。不同候选同时保留，支持多个候选时明确标歧义，不靠历史最近值锁死。
4. 默认33.3ms窗口，不依赖旧空间相位的160ms积累。真实响应速度仍需实测；这不是已经证明33ms端到端延迟。
5. 限最多8块、每块4096事件；溢出显式拒绝，不偷偷按时间抽样。这是CPU原型的资源边界，不是最终吞吐方案。若真实侧视大多溢出，应以GPU流式充分统计量实现，不能直接全量转CPU并不断加上限。

小型合成检查通过：300与600Hz当前候选选择、排除未来事件、平移补偿、随机极性拒绝、缺上游支持拒绝、容量溢出明确拒绝。检查文件output/phase_speed163_20261101/local_temporal_mechanism.json。

这只证明机制能运行，不是独立机械RPM、推力或位置预测收益；周期灯光仍可能通过时间模板。极性对称、基频缺失及混合旋转源可能留下不可判别候选。尚未接入默认链路、未跑真实RAW、未测FPS；此前39.73px及4.87/6.81FPS不变。

原理参考：[DDHF](https://arxiv.org/html/2603.08386v1)的非均匀时间戳谐波特征；[HelixTrack](https://arxiv.org/abs/2603.09235)的相位观测思想。这里使用平移补偿局部时间块，未复制作者实现，不将其当作已完成论文复现。

## 额度允许后按此顺序推进

1. 只用已保存侧视窗口，取当前周期图的局部主要频率候选；事件输入限定为原生桨叶支持，报告通过、歧义、稀疏及容量拒绝各占多少。无需重新解码整条RAW，不读位置标签选频。
2. 若有持续合格局部证据，加入局部块运动续接与相位创新；块的消失/新增只改变分账资格，不等于电机真实变速。未知桨力仍在d。不能把多个块的重复周期重复算成多台电机推力。
3. 和现有池化变化代理作一次同起点对照，只有当前合格变化证据进入二力输入；混合/歧义时保留不确定性，不乘4，不补隐藏RPM。
4. 性能另做单一热点：锁定时有限频带、失锁宽频重发现；复用原生支撑计数/几何，随后做有界缓冲。每次记录新观测年龄和完整P95，而非只看发布FPS。
5. 如果侧视通过数仍为零，先看拒绝原因和时空补偿，不继续无目的调相关性门槛；该原型并不能保证所有侧视都有足够可辨识信号。

当前账户周窗口仍显示已用90%（剩10%）。本批仅代码、轻量合成机制及文献核验；不启动负载实验、不使用重置券。目标仍为0.4秒30px、持续30FPS，尚未达成。无本批后台任务，RAW/模型/保护目录/发行ZIP未改。
