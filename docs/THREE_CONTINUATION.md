# 三桨续接、二力反馈与30FPS计算优化

这是连续五圆共享图像模型的累计改进，入口仍为 `forecast_mainline.py structure-fast`。
传统加速度预测没有重新接入实时通道。原版、旧快通道源快照与控制开关保留。

## 当前逻辑

当前20ms纯ON/OFF计数经固定阈值抑制后提取轮廓。四桨初始化共享六维图像状态
`p_i=c+A r_i`；三桨提供非共线中心约束，两桨只更新可观测方向，近侧视轴线只更新角度。
当前三桨且至少两个独立中心合格时，可以刷新同一个120ms引导窗口；两桨、轴线、
全部由模板引导的中心不能刷新。所有四个模型桨心的不确定性都必须在界内。

新增短弧法线约束：当前原始阈值轮廓与模型椭圆的法线距离修正共享状态，
弱方向保留未知。它不增加“检出桨盘”数量，不单独初始化物体，不刷新引导时间。
形状依赖先前模型，误差代理使用3px共同误差底限，而不是把相邻像素当成独立测量。
当前轮廓支持和周围环带对比必须合格。它与真正拟合出中心的弧恢复是两条不同证据。

完整弧恢复保留原面积IoU门控，另允许当前椭圆内部支持>=.72、25%环带较空的情况，
以容纳机臂粘连。原强弧点数/覆盖/拟合质量门槛没有下调。
接受的当前部分椭圆形状用固定0.2s时间常数慢更新；隐藏椭圆仍来自模型输运。

二力模型是像素加速度 `a=k*u+d`。`u`来自当前相对闪烁频率平方和图像法线，
并非已校准的机械RPM或牛顿推力。k保持有效像素增益，d吸收重力、气动、
投影、增益误差和定位偏差，不能据此分别识别风速、质量或推力系数。

此前d和k共用8行成熟数据的启动条件。现在固定k时，d从首个成熟0.2s位移开始慢修正，
k仍需8行、输入激励和原不确定性资格。学习端点采用与位置状态一致的调整后坐标。
缺当前周期/姿态时，总加速度最多保持120ms，持有不刷新年龄，也不算当前推力测量。
更严格2sigma代理增益门控仅为可选实验；这段数据预测不变，不宣称精度提升。

## 已实现的速度改进

* ON/OFF一次联合直方图，逐像素计数精确相同。
* 几何复用已为频率计算的扩大ROI，保留几何ROI内全部原始时间戳。
* 椭圆不确定性的十次有限差分批量计算；不是缓存过去的不确定性。
* 逐桨和整机周期摘要共享每像素最新记录；异常最新频率时保留原来的筛选顺序。

这些是组件优化，不能直接相加冒充整机测速。当前两秒清晰/三秒侧视完整RAW：
计算能力约30.78/36.08FPS；成功整机观测约26.94/26.86Hz。
短片、启动积压和耗时尖峰仍在，尚未证明持续低延迟30FPS。

## 结果和限制

相同RAW、相同保存的当前整机框60时刻，短弧约束7次，三桨0→2，两个时刻相隔100ms，
中间仍有两桨信息帧。完整RAW也出现2次三桨，尚不是连续三桨跟踪。

旧侧视同14目标：0.4s物理均值57.492→提前d55.948→加短保持56.011px；
组合中位61.834→55.675，但P9584.944→86.756变差。
最新完整侧视13目标同输入对照：旧8行规则53.899→累计52.718px；
离线传统加速度对照35.929px仍更好。两组起点不同，不能把56.011→52.718当作改进。
清晰段没有匹配的独立中心真值，不能用模型画得更完整证明预测准确。

已有扩展状态观察器也做了固定机制试验：共同12目标的0.4s均值54.470→56.268，
P9590.833→146.525，保持实验状态，不部署。直接增加复杂观察器没有解决输入信息不足。

所有评分在输出完成后进行；历史稀疏框、没有同步RPM/姿态/力真值，不是盲测或SOTA比较。

## 控制开关

* `--no-partial-arc-information`：关闭当前短弧法线约束。
* `--guide-full-only --strict-guide-area --no-current-shape-feedback`：保留早期引导策略。
* `--delayed-disturbance-control`：旧8行启动、原整机坐标和无短保持控制。
* `--no-force-gap-hold`：单独关闭加速度短保持。
* `--strict-gain-quality`：可选2sigma代理门控，非已校准置信区间。
* `--legacy-structure` / `--no-shared-arc-recovery`：原结构与无引导控制。

## 方法来源

[官方源码](https://github.com/lagadic/visp)提供轮廓法线与鲁棒模型跟踪的成熟思路。
当前短弧模块为自写NumPy实现，没有复制、打包或调用ViSP代码；不宣称法线距离跟踪首创。
已有147/148弧拟合与资格检查继续复用。新增耦合观察器探针复用项目自己的
`lumped_disturbance.py`，没有再引入一个生产检测器。

下一步应优先解决当前周期代理与有效推力的可靠关联、低延迟尖峰，以及真正持续的部分可见续接。
不应继续把增加桨盘假设数量当作最终目标。
