# 可选低延迟位置模式（2026-10-25）

这一模式补充原有研究流程，目标是在低频发布时及时使用最新观测。它不使用桨盘姿态或物理推力，不替代原有research/rotor-experimental配置。

位置更新与外推现由可安装`event_drone_forecast.position`提供，根目录数学文件保留兼容导入；迁移保持632次实际输入的全部数值与资格不变，见[位置核心](POSITION_CORE.md)。

```powershell
python core/forecast.py run --profile live --config configs/local.json `
  --raw 'E:\dataset\train\6\media\event.raw' --output '<新的输出目录>' `
  --start 110 --duration 4 --tracker-hz 25 --publish-hz 5 --preview
```

## 机制

1. 独立SDK进程通过官方 `EventsIterator` 持续解码原生20ms事件，保持微秒时间戳。主线程与SDK解码不共享Python GIL。
2. 所有原生切片进入SDK噪声/可选周期状态；仅在跟踪节拍复制并传送当前20ms过滤事件。待处理槽只保留最新包。
3. CUDA端在回放计时开始前完整预热预处理、推理和NMS。位置跟踪目标25Hz，复用107位置KF与23稳健加速度；可靠性按实际时间跨度与请求节拍检查，不直接套旧18帧分母。
4. 默认独立定时线程按实际时钟5Hz发布，缺少新鲜状态时仍发布明确无效的心跳。错过截止时刻跳槽，不突发补发。每个快照同时记录观测截止时刻与计算实际可用时刻，发布不会使用尚未完成的状态。
5. 对观测截止时刻t与实际发布时刻t+age，预测目标为t+age+h，补偿已测处理延迟。

`--producer thread` 保留早期线程/旧RawReader实现，主要用于问题复查。推荐独立进程默认模式。`--periodic-axis` 是实验诊断，不参与预测；它增加处理开销，未作为最终低延迟成绩配置。

`--publication-clock tracking`恢复上一轮由跟踪循环触发发布的限频模式。`--body-association bytetrack`实验性调用已安装Ultralytics BYTETracker，将关联结果还原为当前原始NMS框；弱检测不能初始化，空档不把跟踪器预测当新检测。该选项没有提高本轮有效输出，不默认启用。`--noise-model continuous`为固定FilterPy连续时间Q对照，跨录像收益混合，默认仍legacy。

`--frame-transport frames`是新增可选共享画面传输，只支持process生产器；默认仍events。全部原生事件继续进入SDK状态，当前20ms检测画面与5ms预览可用带槽锁/代际编号的共享内存传递。先前31对检测画面与31对预览逐字节一致；其非受控时序差异不能视为稳定整链加速。用户游戏期间暂停测速与RAW/GPU运行，源码正在整理，接线状态见[精简实时源码](LIVE_RUNTIME_SOURCE.md)。

`--startup-sync reader-ready`是可选启动同步：RAW定位完成后先等待，再完成GPU检测预热、打开输出和发布器，最后开始回放计时。默认none保留原顺序。它针对长文件定位后首段观测过旧的问题，不修改运动公式；实际接线及负结果记录在持续记录中。用户已在游戏关闭后恢复负载实验。

## 实测与局限

最新独立定时器试验（`output/live_body_association_v2_20261025`）：train2 6秒/侧视4秒/清晰2秒/空场1秒，共665个原生切片、316次跟踪。发布30/20/10/5次，漏槽0，发布迟到P95约2.045/2.177/2.153/1.415ms。有效16/16/9/0次，**5Hz是发布心跳频率，不是连续有效预测频率**。空场没有有效输出。

同一NN帧、同一实际发布时间对照，强框路径与ByteTrack关联路径有效数量相同；0.4秒近似人工插值参考：侧视n14约51.095/51.088px，train2 n13约73.863/73.856px，差异不能视为增益。这组与下述旧pilot时刻和片段不同，不能交叉比数值声称改进。train2未标注时段的存在性未知，不能把全部无效心跳算作漏检。独立定时器升级解决发布调度，没有证明提高轨迹精度。

上一轮存档（`output/live_forecast_final_v2_20261025`）：清晰2秒、侧视4秒、另一段4秒，共515个原生切片。三段分别发布8/17/18次，其中有效7/15/7次。按完整请求时长计算，发布频率4.0/4.25/4.5Hz，有效预测频率3.5/3.75/1.75Hz。它使用旧tracking触发发布，仍可通过选项复查。

发布时全部观测年龄中位为43.6/26.5/22.0ms，P95为63.8/180.2/34.8ms。侧视180ms尾部未被隐藏；其中过旧条目无效。侧视有效15次观测年龄中位25.2ms、P95 50.3ms。运行中计算中位22.1/20.3/18.7ms。另有13.1/23.1/14.7秒完整冷启动/文件定位时间，不应将运行时计时当作启动时间。

同一4.1秒、205切片的旧RawReader与EventsIterator，x/y/p/t规范字段逐片SHA256完全一致。顺序读取探针中位2.65→1.20ms，排除初次定位后的峰值173.85→29.83ms；系统缓存/负载未受控，不能据此承诺固定硬件加速倍数。

近似精度核查使用相邻人工可见框中心间的线性插值（间隔≤150ms）。对相同观测起点、相同发布时间+h，侧视0.4秒14共同对：live60.21px、旧156状态重外推53.20px；另一段6共同对：86.91/86.07px。旧状态是离线参考，不是同样延迟的实际部署；不能与旧45.594px跨口径比较。**新模式未证明精度提升，默认精度算法保持原样。**

现状是本机按真实时间回放RAW，尚未接入实时相机；也没有推力/RPM或未知录像泛化增益。

## 输出时间语义

- `tracking.jsonl`：每次实际跟踪更新，t为观测截止时刻。
- `predictions.jsonl`：每次发布；t为发布时刻映射到录像时间，`observation_t`为事件截止时刻。
- `predictions`：发布时刻+h；`observation_predictions`：同一状态不补延迟的t_obs+h对照。
- `valid`：发布时刻的有效性；`valid_until_t`记录最近机体观测的保守新鲜度截止，不是经校准的未来误差保证。
- `estimate_available_t`：快照计算真正完成的源映射时刻，不能晚于发布时间。独立定时器额外保存计划发布时刻、迟到时间及跳槽计数。
- `protocol.json` / `completion.json`：配置、源码指纹、目标频率、实际数量、耗时、原生事件数。

原 `score_dense.py` 的默认原点语义用于旧流程；请勿把两套分数直接混用。旧pilot核查脚本为 `tools/summarize_live_pilot.py`，最新时钟/关联对照为`tools/evaluate_body_association.py`。视频固定5fps展示发布画面，真实时间与无效空档以JSON为准。

## 2026-10-26新增的可选项

用户关闭游戏后已恢复RAW/GPU试验。`--scale-rollout compatible` 根据过去完整框的宽高变化兼容性给条件透视高阶修正，默认none。实际小试side 0.4s49.930→48.982px，train2不变；不改变当前位置状态、有效性或推力，固定形状假设限制适用范围。

`--periodic-axis --periodic-sampling fixed-quarter` 用固定SDK像素掩码减少周期观测负载；检测仍读完整流，选中像素没有时间降采样。默认full，周期仍不参与预测。`--reader-index disabled` 只支持process，原生字段等价但未证明稳态速度提升，默认default。

process生产器在保留全部原生噪声/周期更新后，停止已超过160ms的图像生成和传输；这是避免过期工作，消费者原有有效性限制保持。新的实际运行自动保存source_snapshot及manifest，旧ZIP不包含新修改。

`--periodic-packet latest-pixel` 是process+periodic-axis专用可选传输去重，默认full。它只保留当前20ms每像素最后一个合法周期记录及全部非法频率记录（保留排除计数）；完整原生事件仍先进入周期引擎。该包只适合无状态141观测器，不能喂回频率/相位引擎。当前30次观测的摘要、线轴及点全部一致；实际短RAW管道字节6,929,712→1,040,616。不同运行接受时刻与有效数不同，未证明端到端速度/预测精度提升。

最新分工见 [恢复后的优化方向](CURRENT_OPTIMIZATION_20261026.md) 与 output/optimization_resume_20261026/index.html。下面的“接下来”保留上一轮历史状态。

## 接下来（历史记录）

低频位置误差反馈、连续Q、多项式当前速度和更连续的旋转相位都没有一致预测增益，停止继续调权。当前先整理实时入口依赖和可选共享传输；恢复负载实验后先检查小段接线与观测年龄，再决定是否值得升级默认。HelixTrack作者核心仍限本机研究，推力代理尚未接入默认预测。详细正负结果见`OPTIMIZATION_JOURNAL_20261025.md`。


## 新模型候选与评分（2026-10-26）

当前原默认保留；可选单模型参数平均与条件尺度小试见 [候选说明](DETECTOR_CANDIDATES_20261026.md)。跨录像未来误差没有一致提高，不能写成默认升级。--center-ensemble-weights 和 --center-ensemble-sha256 会加载第二个检测器，只在匹配的当前框上平均中心；不减小测量协方差、不添加缺框观测，并增加真实推理开销。

源码 CLI 支持 --detector-weights、--detector-sha256、--sdk-python、--gpu-python、--cache-dir，优先于配置校验，命令行路径相对当前目录。可用 --dry-run 核对选中模型，不启动 RAW/GPU。

tools/score_live_labels.py 接受任意已完成 live 目录和独立 GUI 密集标签，按 publication+h 评分。没有密集参考的时段跳过，不把未标注当缺席。最新候选仍只预测二维可见框中心，没有RPM/推力实测。
