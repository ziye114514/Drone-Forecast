# 阶段168交接：局部周期源续接正式接入纯桨叶入口

## 优先级与边界

自己的ON/OFF桨叶检测、五圆/四三二/侧视分工、可观测贡献＋未知合力是主线。NN只作辅助观测，拿掉自己的部分仍一样好不能作为创新成功证据。本轮正式候选不需要NN，未改NN或模型权重，未训练、上传或更新ZIP；两处yolov10/RAW未动，无子代理/新依赖。

## 本轮解决的实际问题

### 局部周期连续性

此前`local_pixel_phase`每帧选最受支持的主频，缺少局部来源续接。新`local_period_tracks.py::LocalPeriodTracks`：

- 复用当前已通过原生模板检验的局部区域和频率候选，scipy匈牙利关联机体相对64px网格。
- 允许1.5格位移，用原bank的`log(4/3)-.08`变化门槛，只选择当前存在的已验证频率，绝不除2捏造缺失基频。歧义保留，区域不是电机编号。
- 至少2个连续当前区域才能出共同变化输入。不同区域可有不同实际频率，不要求四桨等速；对它们各自的log频率增量取中位形成相对输入，不按当前像素密度选全局主频。
- 新增/消失区域不直接制造推力阶跃；.12s断档、支持全部更换时转新参考，当前缺失立即撤销资格。
- 输出的等效频率`300*sqrt(relative_proxy)`只是归一化接口量，不是真RPM或已测总推力；隐藏桨仍在未知项。归一化参考越界时重启，避免永久失锁。
- 四/三/部分二桨仍用当前逐槽证据，不强凑四桨，不补隐藏RPM。只有轴线/无法建完整结构的混合路径用局部续接。

`RotorThrustBankProxy`仅对带`same_source_spatial_tracking_confirmed`的新可选输入允许原先已有的约23%变化门槛；旧调用仍.08。不是宣称空间关联独立证明真实转速；倍频/快速真阶跃仍有歧义。

### 二力的正确接线

首轮`InnovationUnknownForce`用未知力状态和创新代替每帧`d=a-k*u`直接抵消。它有正例，也会因重复滤已滤过的净加速度造成滞后，**不升默认**。

正式候选直接复用原`RelativeRotorForceObserver`：同一个位置/速度/未知力观测器，只换连续桨叶输入。真实同源变化先作用；新/失去的贡献只转移已知/未知分账，不造假加速。当前数据没有新NN预测分支，也没有额外未知力滤波器。固定k200，把来源机制与放大k分开。

新CLI：`--rotor-track-local-source`，必须同时`--rotor-local-phase`，已接`run_rotor_only.py`和`run_fast_structure.py --rotor-only`；默认关闭。拒绝配合旧hidden-prior分账使用，避免语义混用。

### 纠正167纯桨叶回放频率解析

`period.frequency_hz`存的是全局像素中位数，live bank选择局部时实际用`local_temporal_phase.frequency_hz`。旧`pure_observation`错误地把前者标成局部来源；现按实际来源取值。

因此此前纯桨叶可用数63/2不是正确基数；正确旧解析81/21，新续接94/36。**不要再宣传错误基数上的倍数**。167的NN辅助观测带不受影响；167纯桨叶周期贡献只能按旧错误解析身份引用，不能当严格live复原。

正式新输出另存`period.selected_frequency_hz/selected_frequency_source/selected_frequency_is_normalized_proxy`；即使selected值为null也尊重它，不能退回全局读数冒充当前选择。原`frequency_hz`旧字段保留，防止破坏兼容。
