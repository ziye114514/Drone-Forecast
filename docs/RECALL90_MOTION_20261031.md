## 已落实

1. 复用原小目标模型，并做一次固定5轮33.333ms域适配：FRED3/4/5训练、6验证，混合原自采1/4弱标签。评分0/1/2/7/8/9/10不进入该轮训练；最佳权重仅按验证集选取，没有在评分段反复选epoch。729张训练、216张验证，具体以协议计数为准。旧权重不覆盖。
2. 一套共享Singer状态联合估计p/v/未知净加速度，继续原力学积分。tau=.35秒、噪声6px沿用；加速度sigma=原3000上限/3，未在评分段扫参。矩阵指数与原解析积分最大差4.55e-13，Q正半定。没有增加并行轨迹滤波或测到真实桨力。
3. 修复获取死循环：小目标NN延迟答复无法通过稀疏LK转移，反复丢弃已检出目标；新候选失锁时取当前NN，并计入阻塞耗时，不把旧框冒充当前框。
4. `CurrentBoxGate`使用当前真实NN/当前图像位移与近期NN进行关联，99%卡方门、6px噪声及既有加速度上限；拒绝框记缺失，0.5s失锁后允许重新获取。FRED10原两帧错配把目标从约1015px跳到595px，产生1514/1012px预测。门控后旧小目标模型配置源均值174.13→47.29，同16墙钟查询91.63→59.02px，当前119/120。该诊断不是新33ms模型的FRED10成绩。
5. 无模型、小目标、9次更新完全无有效结构时，仅几何以10Hz重新搜索，NN/状态和每个原生周期输入仍保持原频率；不把缓存几何叫当前观测。有任何结构后恢复完整处理。当前原主入口不启用此降频。
6. 初始化前加载有限助手、预热非空重叠NMS与Singer矩阵，启动耗时另计。修复关闭structure-guided-nn时局部import遮蔽全局函数而导致UnboundLocalError的旧缺陷。ByteTrack调用频率参数按新NN节奏修正，但其候选丢失太多，不采用。

这些FRED小试没有合格逐桨推力/四桨几何，收益来自定位、共享状态和调度，不能宣传五圆或RPM优势。

## 使用

从项目目录运行小目标候选（本机已有SDK/Numba环境）：

```powershell
python run_fast_structure.py --raw '<events.raw>' --output '<新目录>' --start 32 --duration 4 --sdk-avx2 --structure-guided-nn --recall90 --detector-model 'models/small_target_native33_v1.onnx' --detector-sha256 fc228a1b355a3b8396c05df63f7eb8beaf192bca758bf5089898e16e893a4255
```

`--recall90`是目标名称，不是认证；组合完整包NN、共享Singer、当前获取、身份门控、无结构时stride3几何。`--unresolved-geometry-stride1`保留完整几何频率。原`--realtime30`、`--legacy-realtime30`及原模型保留，大目标自采侧视仍优先原入口；不能将新模型全局覆盖。
