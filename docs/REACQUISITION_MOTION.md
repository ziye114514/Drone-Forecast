# 部分框扩张、运动资格与搜索调度（2026-10-29）

本批沿用五圆／独立侧轴、周期有效推力和总扰动反馈。修的是其共享位置／速度入口，没有重新添加传统并行预测器，没有把光流称作桨叶推力。

## 已接入候选的修复

`run_fast_structure.py --target-candidate`现在允许：弱框中的一个已跟踪区域，被新的强整机框包含时，沿用该区域实测的刚体位移来约束速度。用`--no-contained-reanchor-motion`恢复原门槛；非候选运行可显式加`--contained-reanchor-motion`。

重入画面时，原来的小框可能只覆盖机体一部分。强NN识别出更完整机体后，框宽骤增，中心也随之跳动。中心差不能直接当运动，但原区域的双向图像跟踪仍可能可靠。原门槛要求两个框IoU≥0.5，或旧框本来就是强框；它会丢掉这类真实位移，使共享KF在最需要速度时被形变误导。

新增许可同时要求：当前强NN锚、旧弱框置信度≥0.25、投影后的旧区域被新框包含≥80%、面积比≤4、≥12个当前双向跟踪点、相似变换≥12内点且比例≥75%、位移方差最大特征值≤9px²。沿用现有包含率、面积比与严格刚体支持尺度，没有按未来误差搜索门限。当前整机框、置信度、定位资格和桨盘几何资格均不升级。

它复用已经计算的OpenCV LK点对和RANSAC相似变换，无额外图像流计算。相似变换仍在已有参考中心求位移；所谓去掉中心跳变，是不用“部分框中心→完整框中心”的差来计算速度，并非不使用参考中心坐标。

## 可复查的收益

新空场调度的一次侧视运行在116.465502秒重锁：旧小框到新强框中心跳动约60px，原速度约+69px/s，图像位移却支持约−885px/s。保留实测位移使该起点0.4秒误差397.63→20.85px。此前口头约79px是错误反算，精确逐点结果见JSON。

第一版把跨参考的局部速度也加入加速度历史，导致116.632167秒35.66→90.01px。最终版明确将此过渡样本标为`derivative_eligible=False`：用于当前速度，不加入加速度／未知力求导历史；后续完整机体参考的当前位移照常使用。不是提高等待门槛或临时关闭整条物理分支。

最终同一批观测、同24个原起点45.8844→30.1854px，只有上述重锁起点预测改变，后续原有预测不再退化；当前框、有效预测时刻、几何和周期不变。初版32.6095px及其退化保留在`replay/`，最终版在`replay_velocity_only/`。六条原／新冻结观测流都先复原原计算，最大差为0；原侧视26起点31.6214和另一段15起点59.7896保持不变。FRED 7两条各120帧冻结观测预测亦逐项不变。这是特定失效机制的修复，不是跨数据集提升证明。

新的完整RAW运行与严格同输入控制分开报告，见`../../output/reacquisition_motion_20261029/index.html`。每次保留原起点的漏失记录；不把减少评分数量后的均值当全覆盖成绩。

## 仍保持可选的两项工程改动

- `--empty-search-stride`：最初0.3秒保持密集搜索，之后从未见过／长期缺席的目标按普通NN stride搜索；最近0.3秒有真实图像观测的失锁仍立即搜索。30Hz、stride=3时冷搜索为10Hz，最多约0.1秒等待，短暂目标可能漏掉。两段实际结果都有获取时刻变化，不能默认推广。
- `--raw-slot-events 3000000`：每个RAW／过滤事件共享槽由2M增到3M，带过滤时共享内存128,000,000→192,000,000字节。60个原生截止窗的x/y/p/t字段与过滤结果完全一致，大包队列回退6→0；旧回退也保留完整事件。它没有消除全部解码停顿；默认仍2M。

相邻时间原调度对照同样很快，说明早前531→16ms之类跨次变化不能全归功于降频。当前必须分别报告固定可见窗口处理能力、实际观测率、完成滞后、原起点覆盖和误差，不把空场吞吐当检测FPS。

## 复现

```powershell
python core/run_fast_structure.py --raw '<event.raw>' --output '<新目录>' `
  --start 110 --duration 8 --target-candidate --sdk-avx2 `
  --rigid-motion --structure-guided-nn --paced
```

本机SDK／Numba路径见已有运行配置。测试脚本`tools/probe_contained_reanchor.py`含受控中心跳变和不合格观测拒绝检查，以及依赖本机冻结记录的回放；它不是独立RAW测速工具。`tools/score_transport_search.py`仅在预测保存后读取人工框。

已有[OC-SORT论文](https://openaccess.thecvf.com/content/CVPR2023/papers/Cao_Observation-Centric_SORT_Rethinking_SORT_for_Robust_Multi-Object_Tracking_CVPR_2023_paper.pdf)讨论失锁重获时的运动估计误差；这里没有复制其代码或使用它的虚拟轨迹重更新。LK与相似变换来自[OpenCV官方接口](https://docs.opencv.org/4.6.0/dc/d6b/group__video__track.html)。本修复是项目工程贡献，未宣称首创。
