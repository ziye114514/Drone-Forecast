# 2026-11-01 阶段160：桨叶原生入口接入预测

已实现可选的完整RAW入口。旧默认整机NN算法保留；需要显式选择`--rotor-only`，不是打开旧入口后自动使用新桨叶前端。

## 实际流程

RAW(x,y,t,p) → ON/OFF计数与密度筛选 → 过去半窗发现周期、当前截止前的后半窗验证 → 周期种子选择原生双极事件连通成分 → 原生轮廓/桨盘椭圆与五圆/部分可见/侧视轴分支 → 共享位置速度净加速度状态 → 可见周期有效推力代理 + 到期位置残差合并未知作用 → 源时刻后0.1/0.2/0.4秒预测。

- 新入口不读取NN权重或G重建，不需要整机框提供ROI；保留字段名body是为了兼容旧几何/力学接口，实际位置框来自桨叶信号。
- 过滤PNG不是原图叠色；掩膜外像素确实为0。保存原始、密度、严格周期、原生弧段四种图与数值掩膜。
- 周期检验很严格，单靠它只剩局部亮点。用周期种子在当前原生ON/OFF连通支持中重建轮廓，再回到真实事件像素做几何；不把膨胀产生的边界当物理桨缘。重建保留的像素不等于每个像素都通过周期检验，连到机体的活动也仍可能残留。
- 位移匹配仅读取上述筛选后的ON/OFF数组，没有再读取附近未经筛选的机体纹理。
- 四桨复用RotorThrustBankProxy逐桨频率平方求和；缺桨最多保留0.12秒单桨先验，隐藏桨不是实测，部分输入不用于新的增益学习；侧视使用无身份的池化周期代理，不要求先恢复四个椭圆。
- 每个当前椭圆内部的合格周期像素提供单桨频率；谐波、叶片数和真实RPM换算仍未解决。法线正负使用图像向上先验，未恢复完整三维姿态。
- 几何降级时仍可能组合当前周期与模型法线；完整当前四桨周期资格很少，不能把所有active输入称为四桨实测推力。

## 速度

复用已有CUDA谐波代码，新增常驻共享内存适配器，使SDK Python3.11与本机CUDA Python3.13连接，不加载检测器。空间运算复用OpenCV，不拷贝新的第三方实现。

清晰CPU初版计算能力约1.16FPS，CUDA+空间优化后约3.92FPS，侧视约3.89FPS；记录含首帧冷计算。含当前PNG/视频/诊断导出的整个回放更慢。它仍远低于持续有效30Hz，不能用源数据30Hz或视频播放30FPS冒充运行帧率。GPU周期验证和全幅数组/形态运算均有成本，后续应减少重复全幅处理，让稀疏周期计算驻留设备，并保留全局失锁重发现。

## 检查与边界

- 九个真实保存窗口的原生轮廓/密度/闭运算掩膜与原参考一致；清晰CPU和CUDA版本当前框中心最大差0px（仅所测窗口，不宣称CUDA浮点普遍位相同）。
- 加入大量未来事件不改变当前计数、周期掩膜或频率；过滤图掩膜外为0，几何保留像素均有原生事件。
- 力输入开/关使用同一位置观测；原力输入可因果回放到误差<1e-7px。
- 真正RAW执行主入口空场约两帧，输出3个包，证明`--rotor-only`无需模型权重可运行。
- 原模型ed801 SHA保持不变；未来GitHub导出依赖已登记新模块，未重建/上传ZIP。
