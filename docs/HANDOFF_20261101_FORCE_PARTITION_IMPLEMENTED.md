## 本批实际改动

1. `rotor_thrust_bank.py`：原bank原样保留为LegacyRotorThrustBankProxy。新默认只求当前可靠可见槽贡献，隐藏桨力归未知d；不再等四路周期首次同时合格。当前槽映射仍需要可用几何，不能把“bank允许部分启动”写成“任意两团事件均能冷启动五圆”。
2. 固定标度`sum(f_visible²)/(4*300²)`。300Hz只是输入单位约定，分母的4只是固定参考单位，并非推测四台电机均以300Hz转动；分子没有隐藏贡献，也不按可见数量重新归一化。有效增益k仍需学习，未标定真实牛顿推力。
3. `rotor_force_observer.py`：显式接收观测贡献及不确定度；失去当前资格就立即从可测项转入d，不把旧桨力继续挂在可测项0.12秒。集合切换只转移新增／移除贡献，同一保留槽的真实频率／法线变化继续影响加速度。使用Jacobian转移k相关协方差，并对输入误差作保守独立近似；误差并未实测标定。集合切换清空激励历史，暂停不可靠增益学习。
4. 侧视/未建模混合谱：使用`(f_pool²-f_anchor²)/(4*300²)`变化代理；基线、隐藏贡献和其他力均归d。它不是已测两桨或四桨推力，不乘4，不学习混合信号的推力增益，混合源成员变化仍可能造成假变化。
5. 原8%变化门槛会使同桨20%转速阶跃丢资格，重锁后又被分账重锚抵消。本批对已映射同槽采用`abs(log(f_new/f_old)) < log(4/3)-0.08`，避开前四阶谐波最邻近比4/3的边界；8%以上的快速变化按三倍代理误差处理并冻结当下增益学习。这是有限阶谐波假设，不是RPM精度证明；侧视混合谱仍保留较严资格。
6. `rotor_cuda_device.py`：稀疏activity/period/native打包为一次D2H拷贝，保留三次拷贝对照`DeviceRotorFront(fused_sparse_copy=False)`。数据值不变；不宣称所有片段都更快。
7. `run_rotor_only.py`、`run_fast_structure.py`接线；新增`--rotor-legacy-decomposition`复原阶段161的bank＋联合状态控制。`--rotor-legacy-force`同时保持更早的bank／残差控制；原NN入口不变。启动前保存源码快照，结束检查是否修改，避免把运行中导入的旧代码错误归给结束时的新源码。

没有G重建，没有以整机NN作前置。机头机尾不要求辨识；槽号只是观测分账索引，全四桨Σf²仍与编号置换无关。RAW、两处yolov10保护目录、模型和已发布ZIP未改。
