# 0.4s平均误差50px与30FPS目标

目标先沿用当前平均欧氏误差口径，同时报告P95与50px内比例。如果要求每次预测均低于50px，难度与均值完全不同，当前没有达成任何这样的保证。

候选运行：

```powershell
python run_fast_structure.py --raw E:/dataset/train/6/media/event.raw --start 110 --duration 4 --output ../output/my_goal_run --goal-profile --paced --verify-frames
```

`--goal-profile`启用已有等价计算优化、异步NN、子进程同规则SDK降噪，以及本轮的当前侧轴/完整桨盘多速率调度、近期未知力修正与Singer外推。推理只读RAW和固定权重，不读标签。它是候选配置，不是性能保证。原力学默认和原计算`--reference-compute`均保留，已发布ZIP未重新打包。

侧视每帧仍使用原生20ms密度、原PCA/LSD/多阈值资格，只有上一轴资格有效、当前仍合格时才省去部分独立conic搜索；每3帧完整搜索，当前资格失败立即返回全搜索。省算的帧上桨叶数量是“未重新判定”，不是少看见几桨；不造桨心、不把模板当当前完整姿态。清晰四桨仍走全模型，当前仍较慢。

未知力与有效推力增益分开时间尺度：增益保持原慢学习，未知总加速度d使用已经成熟的0.2s积分位移残差，权重随0.2s时间尺度衰减，修正时间尺度0.1s。原位置p/v不变。净加速度未来期望采用固定0.35s相关时间，数学形式见[Stone Soup Singer文档](https://stonesoup.readthedocs.io/en/latest/stonesoup.models.transition.html#stonesoup.models.transition.linear.Singer)。这是未见未来控制量的外推先验，不是重力或风本身衰减；并非原创Singer模型、绝对牛顿推力或真实质量/风速识别。

本轮实际结果：

| 原生RAW | 处理能力 | 当前整机观测 | 0.4s平均误差 |
|---|---:|---:|---:|
| side110–114s | 33.60FPS | 28.13Hz | 52.01px，18目标 |
| clear26–28s | 19.17FPS | 17.74Hz | 无独立人工框 |
| train2 40–46s | 70.08FPS | 17.80Hz | 67.97px |
| 前加0.5s真实过去，仍评分110–114s | 17.33FPS | 14.10Hz | 63.04px |

不能把一段的速度和另一段的误差组合宣称达标。处理能力大于30也不表示有30次当前整机观测；缺测和有效预测数量单独保留。side同一套新观测上的旧力学65.89→52.01px，新P9595.83px，仅8/18目标在50px以内。候选仍未同时满足目标。

过去0.5s出现每窗超过200万事件的强突发。修复前固定共享槽报错，修复后保留全部原事件经有界不可变包传输，最大2193664事件、6次溢出；复制/过滤/解码仍拖慢，不能把修复完整性称30FPS突发吞吐已解决。

`--parallel-period`、`--body-association`均是可选实验：前者本批速度更差；后者复用安装的Ultralytics ByteTrack，只取当前NMS框，未改善本批整体连续性。响应校准、力驱动位置KF、速度创新和局部积分力平衡均留在实验文件/输出内，没有因局部中位数收益就默认混入，也没有删除这些结果。

评分仅使用原有暴露的开发人工框，间隔≤150ms才插值，5Hz源评分、30Hz原生推理；没有新的独立测试集/RPM/物理姿态/推力真值。模型开发使用这些已知片段，存在选择偏差，不宣称泛化或前沿成绩。

下一步优先清晰四桨共享模板的多速率当前约束，配合逐槽周期归一化，严格区分可见数量与计算预算；再处理事件风暴的复制/过滤开销和变向输入质量。train2缺少合格周期，整机召回也需要改进，单靠未知力学习不够。

后续保留一项等价小优化：在单个完整conic尺寸确定后，提前拒绝必定被原最大尺寸1/2.5规则丢弃的候选，省掉不影响最终结果的残差和不确定度。原同步NN/原力学配置清晰段60个时刻输出逐项相同，完整短测22.19→23.15FPS；系统抖动存在，不承诺固定4.3%收益。固定部分遮挡窗重复3次，不确定度计算21→12次，组件14.24→13.30ms。原目标异步预设清晰段19.17FPS与此配置不同，不能直接相减；50px/30FPS目标仍未完成。
