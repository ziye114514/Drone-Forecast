# 独立侧视输入与变向响应（2026-10-29）

后续已修复部分框扩张时的速度资格，并将跨参考的过渡位移与加速度／未知力求导分开，见[最新修复](REACQUISITION_MOTION.md)。最新实际RAW默认侧视31.74px（25/26原起点），另一段58.93px（14/15）；以下保留前一批证据与历史坐标修正。

用户约束：侧视不要求先建立五圆，不要求给桨编号；整机侧轴加桨叶周期可以提供相对推力线索。当前仍是二维图像有效加速度模型，不能把一个显著周期直接当完整四桨总推力或牛顿力。

## 当前采用的改动

`run_fast_structure.py --target-candidate`加入侧视位置一致性历史的参考坐标修正；`--no-position-history-rebase`保留原控制。没有增设传统并行预测器、位置滤波器，也没有改当前整机框或把隐藏桨当观测。

问题发生在当前强NN重新给框时：尺寸/可见范围变化会使框中心相对已测刚体位移跳动。旧代码已经避免把这个跳动当速度，却仍将跳动前后的中心混在加速度的“位置历史一致性”检验中，使真实制动斜率被拒。

`position_history_gauge.py`只在当前稳定的整机侧轴、强NN、小尺度参考平移和可靠当前刚体位移下，把旧一致性坐标统一平移到当前参考。它不改当前定位、共享Kalman位置状态或原始流速度。四桨/三桨/非扁平两点几何不走这个侧轴修正；不需要曾经见过四桨。

条件复用既有工程尺度：位置6px、最大参考平移12px、当前位移方差≤9px²，以及原切向合力使用的侧轴稳定门槛。大幅或无法解释的重锁仍不强行修正。

- 固定原观测，侧视26个原起点：0.4秒均值34.6049→31.6214px，P95 72.5433→60.8614px。主要来自117.632157秒：已有约1000px/s²制动线索被旧位置门槛拒绝，104.21→26.64px。其余起点几乎不变，不能当跨场景泛化证明。
- 另一段15起点和FRED 7固定观测逐项不变。
- 新侧视RAW也完整跑通；其自身同25起点、同观测旧/新计算38.3967→36.0491px。新RAW只保留旧26起点中的25个，与旧观测对应25起点35.3814相比仍略差，不能隐去检测异步时序变化。
- 使用可选截止余量等待的另一次侧视RAW为31.5700px，同次观测旧计算34.4235px；它也是25/26覆盖，尚未证明稳定30px。
- 700px/s²受控运动、静止目标框形变、当前位置/原始轨迹观测不变检查通过。小幅内部纹理运动可能低于现有位置噪声；没有宣称已经分开所有内部桨叶运动和机体平移。

## 0.4秒误差的解释

同时存在“后续运动变化”和“当前线索未被正确使用”。43.432899秒另一录像的前/后两个0.2秒平均速度约为(-318,-48)与(-196,+181)px/s，后半窗明显向下转弯；117.632157秒则已有制动线索却被门槛丢掉，属于可修复实例。

未来有变向，不等于所有误差都不可避免。只有此前输入没有相关线索的新控制变化才无法提前确定；现有位置标注不能证明原始事件里不存在更早姿态/周期线索。反过来，把当前位置误差与未来误差简单相减，也不是严格误差分解。

诊断脚本只在预测冻结后使用人工框。过去位置二次拟合的外推方差很大，不能凭其统计门槛得出“多少比例不可预测”；半窗速度变化也包括可预测的持续加速度，不能当随机指令标签。运行预测器没有读取这些标签。

## 显式时序实验

`--deadline-nn`仅在paced模式下，利用当前33ms截止余量等待已经提交的NN答复；预留最近下游计算，上限为半周期。它没有新增网络，但现有请求调度随观测改变，实际NN次数不保证不变。等待耗时已计入localize/compute，并独立记录。

该选项默认关闭。一次侧视得到31.57px不能代表稳定改善，另一段和完整延迟仍需与各自同输入控制一起看。固定前4秒处理能力，侧视修正版35.64FPS，截止等待版33.09FPS；全8秒缺席时段的吞吐不能作检测FPS，仍有数百毫秒长尾滞后。
