# 第十一阶段：逐桨身份——判据更正与关联实验

输出：`D:\drone forecast\output\stage11_rotor_identity_20261017`（含两个窗口的`identity.json`与`阶段结论.md`）。

本阶段**只读**已经冻结的第十阶段JSONL，不解码RAW、不重跑推理、不改阶段6–10与`src`任何文件。它回答两个问题：第十阶段报的“串桨”判据对不对；以及逐桨身份到底能不能维持住。

## 1. 判据更正（重要）

第十阶段用“相邻两个四桨tick的最优对应是**奇排列**”当串桨判据。**这是错的**：平面四边形的四个循环旋转里有两个是偶排列、两个是奇排列，所以排列奇偶跟“能否由刚体运动实现”没有关系。

平面刚体运动**不能改变的不变量是取向**：把四个点按固定标签顺序连成多边形，其有向面积符号。相邻两帧之间符号翻转、且四边形非退化，就是一次真实的两个桨身份互换。本阶段用这个判据重算，并保留退化判定（各向异性≤0.02 或 |面积|/间距²<0.05 时不判）。

## 2. 关联实验（同一批tick上比四种标号器）

|标号器|做法|
|---|---|
|`serialized_order`|按前端本帧给出的顺序编号（下界，不是真方案）|
|`cv_hungarian`|**现任**：逐桨匀速预测+匈牙利+门控（等同v0.3 `RotorSensing`/`RotorTrack`，`track_expiry_s=0.3`）|
|`rigid_orientation`|整机共享一个相似变换（旋转+等比缩放+平移）；四↔四时穷举**保取向**的排列取残差最小；混合桨数时用变换预测+匈牙利；门控与现任同尺，保证比的是运动模型而不是门限|
|`cv_shape_memory`|在现任基础上加**跨空档身份记忆**：≥3桨时把相对几何（机体坐标系）存下来，空档>0.5 s后重新出现时按形状+保取向做相似匹配，复活旧ID而不是新发|

评价是**无标签**的：用几何本身把相邻四桨集合串成机体坐标系，好的标号器应当让每个身份在该坐标系里的位置基本不动。指标为“身份跳变”（相邻已判定tick之间，某身份在机体坐标系里位移超过0.6×桨间距）。

## 3. 结果

窗口A：train6 第108–120秒（12 s，含近距侧飞与两次空档）。窗口B：train6 第0.01–90.35秒（9035 tick，来自被中止的全程运行的已落盘部分）。

|窗口/方法|四桨tick|取向翻转|serialized|cv_hungarian|rigid_orientation|cv_shape_memory|
|---|---:|---:|---:|---:|---:|---:|
|A strict10|120|**0**|12.31%|1.37%|1.60%|**0%**|
|A neighbor10|147|**6**|10.63%|1.99%|**0.57%**|7.05%|
|B strict10|1430|**59**|6.58%|2.30%|**0.57%**|2.01%|

- **更正结果**：第十阶段说strict10“6次串桨”是**假阳性**，几何上0次；neighbor10的6次都集中在110.0–110.1 s，且“保取向最优对应”的残差高达48.6–78.8 px——那说明那几帧四点根本不是同一个刚体四边形（近距侧飞时候选合并/退化），不是干净的身份互换。真正的标签翻转在窗口B：59次、残差多在3–6 px、分布在20–79 s。
- **现任关联不弱**：逐桨匈牙利把串行顺序的10%量级跳变压到2%左右。
- **刚体+取向约束最好**：窗口B 2.30%→0.57%（4倍），窗口A的neighbor10 1.99%→0.57%，同时明确拒绝31次（窗口B）/19次（窗口A）取向翻转的对应。
- **“长记忆按位置续命”有害**：`cv_shape_memory`把过期时间从0.3 s放到1.5 s后，窗口A的neighbor10从1.99%涨到7.05%——短空档里靠位置外推续命会把身份接到错误的桨上。
- **形状记忆的收益是churn而不是精度**：身份数从185降到81（窗口B）、39降到18（窗口A strict），但复活残差贴限（残差/容差=0.37、0.82、0.97、0.86），还不能算可靠；而且真正的“复活”路径只在空档>0.5 s才触发，窗口A只触发1次。
- **轨道寿命**：cv中位0.49–1.5 s；rigid中位0.05–1.8 s但身份更一致——rigid的失败方式是“宁肯新开ID也不接错”，对下游逐桨转速累计是更安全的失败方式。

## 4. 结论与下一步

1. 逐桨身份**可以**在关联层维持住：错误率约0.6–2%，`rigid_orientation`是当前最好的方案，代价是身份数变多。
2. 身份错误不是主要瓶颈；**轨道断续与身份重置**才是要处理的（每个新ID都会把逐桨频率状态清零）。跨空档续命必须用**几何**而不是位置外推；形状记忆方向对，但门控还没到能用的程度。
3. 侧飞/近距段的“翻转”多半是四点本身不构成刚体四边形（残差50–80 px），说明那里的问题在**观测**而不在关联：候选合并、退化、被别的东西顶替。这与第十阶段“碎片集中在110.4–110.9、112.9–113.2”一致。
